# 冒険者ギルド運営シミュレーション 仕様書

- 版数: 0.9（ドラフト）
- 最終更新: 2026-07-18
- ステータス: 主要システムの方針確定 / 経済・判定・遭遇の初期値たたき台あり（§12）

## 1. コンセプト

> プレイヤーは辺境の町の**ギルドマスター**。冒険者を雇い、舞い込む依頼に派遣し、
> 報酬をやりくりしてギルドを設備投資・人材で強化していく、**ターン制の経営シミュレーション**。

- 一番の楽しさ（コア体験）: **経営・数値管理**、とりわけ**編成パズル**
  - 「どの依頼を受け、**誰を何人**送り、何に投資するか」を毎ターン判断する意思決定の手応え
  - リスク（依頼の失敗・冒険者の負傷）とリターン（報酬・名声）の天秤
- 冒険者は多彩な能力を持つ「経営資源」。戦闘職だけでなく**非戦闘職**（荷物持ち・学者・採掘師など）が
  依頼によっては主役になる
- **普遍的な最適解（最強編成・最適人数）は存在させない**。依頼の内容・経路・目的と手持ちの
  人材の噛み合わせで、毎回考える必要がある状態を目指す

## 2. ゲームの基本構造

### 2.1 進行形式

- **ターン制。1ターン = 1日**
- ターン中はプレイヤーの操作フェイズ（受注・編成・投資）→「日を進める」で解決フェイズ
- リアルタイム要素・放置要素は入れない

### 2.2 コアループ

```
① 依頼が掲示板に届く（毎朝、数件が追加・古いものは期限切れ）
        ↓
② 受注する依頼を選ぶ（同時進行数はギルドランクで制限）
        ↓
③ パーティを編成して派遣（人数・構成・補給・方針が成果とコストを左右する）
        ↓
④ 日を進める → 派遣中の依頼が全自動で進行、道中の遭遇も自動解決、帰還時に成果判定
        ↓
⑤ 報酬・名声・回収品を獲得（失敗なら違約金・負傷）
        ↓
⑥ 収入で 雇用 / 施設投資 / 装備支援 → より難しい依頼が受けられるように → ①へ
```

### 2.3 勝敗・ゲームの終わり

- **敗北条件**: 資金がマイナスのままターン終了時の支払い（給料・維持費）ができない → 倒産
- **勝利条件（初版）**: ギルドランクを最高位（S）まで上げる
- クリア後はフリープレイ継続可

## 3. キャラクターシステム

### 3.1 能力の3層構造

キャラクターは「能力値 × スキル × 特性」の3層で表現する。
職業（クラス）は固定の枠ではなく、**スキル構成に付いた肩書き**として扱う（応募者の分かりやすさのため）。

**① 基礎能力値（6種、1〜20）**

| 能力値 | 主な用途 |
|---|---|
| 筋力 | 近接戦闘、運搬量 |
| 耐久 | 生存性、負傷しにくさ、長期任務への耐性 |
| 器用 | 罠解除、採掘・工作、射撃 |
| 知力 | 学術調査、鑑定、魔法 |
| 感知 | 索敵、危険察知、隠密 |
| 魅力 | 交渉、士気、護衛対象の受け |

**② スキル（Lv0〜10、能力値と組み合わせて判定に使う）**

| 系統 | 例 |
|---|---|
| 戦闘系 | 剣術、弓術、攻撃魔法、盾防御 |
| 探索系 | 斥候・隠密、罠解除、追跡、地図作成 |
| 学術系 | 考古学・古代語、鑑定、薬学 |
| 技能系 | 採掘、採取、運搬、料理、応急手当、鍛冶 |
| 対人系 | 交渉、指揮、荷役管理 |

**③ 特性（トレイト。パッシブな個性）**

例: 夜目（暗所ペナルティ無効）、頑健（負傷日数短縮）、大食い（補給消費+50%）、
臆病（凶悪遭遇時に離脱判定）、カリスマ（同行者の士気+）など。
プラスとマイナスの両方を持たせ、給料と釣り合わせる。

### 3.2 職業（肩書き）の例

応募者は肩書き付きで現れるが、実体はスキルセット。育成次第で複合職化も可能。

- **戦闘職**: 戦士、弓手、魔導士、盾持ち
- **探索職**: 斥候、罠師、狩人
- **非戦闘職**: **荷物持ち**（運搬特化・回収量を増やす）、**学者**（遺跡調査の成果品質を上げる）、
  **採掘師**（採掘依頼の主役）、治癒師、料理人（長期任務の補給効率・士気）、交渉人

### 3.3 その他

- 所在: 待機 / 派遣中（身体の状態とは別軸で管理）
- 身体の状態: 健康〜死亡までを一本の「状態異常ラダー」で管理（§3.4）
- 報酬: **報酬分配が主、基本給が従**（詳細は §6 給与体系）。未払いは士気低下→離脱
- 成長: 依頼で実際に使ったスキルに経験が入る（使った能力が伸びる）
- 雇用は「応募者リスト」から。名声が高いほど良い人材・珍しい職が応募してくる

### 3.4 状態異常ラダー — 負傷・死亡・蘇生（確定事項）

**負傷と死亡（死体の状態）は、生死をまたぐ一本の「状態異常ラダー」として統合して管理する:**

```
健康 → 軽傷 → 重傷 ‖ 健全な死体 → 損傷 → 白骨 → 灰 → 魂魄 → 魂の破片
（‖ が生死の境界。左側は生存中、右側は死亡中）
```

- **生存側は時間で回復する**（重傷→軽傷→健康。医務室・治癒師で短縮）
- **死亡側は放置で悪化する**（回収されず現地に残された死体は **5ターンごとに1段階悪化**。仮置き）。
  同じ軸の上で、生きていれば良くなり、死んでいれば悪くなる
- 回収してギルドに安置した死体は悪化しない（死亡中も基本給を払って蘇生時期を選べる、
  という §6.1 の設計と整合させるため）
- 派遣中に死亡した場合、死体は運搬対象になる（運搬力を圧迫する）。
  持ち帰れなければ現地に残す＝悪化が始まる

**負傷段階の扱い**

| 状態 | 効果（たたき台） |
|---|---|
| 軽傷 | 全能力 −25%。派遣は可能（続投させるか休ませるかの判断が生まれる） |
| 重傷 | 派遣不可。回復まで約10日（軽傷は約3日。医務室で短縮） |

**死亡と蘇生の基本方針: 死亡はするが、蘇生可能。完全なロストは「プレイヤーが能動的に解雇した場合」のみ。**

- 死亡したメンバーは名簿に「死亡」状態で残り続ける。蘇生するか、解雇（＝弔って手放す）するかは
  プレイヤーの判断。システム側から勝手に消えることはない
- 死亡直後の初期状態は死因で決まる（通常の戦死→健全〜損傷、ドラゴンの炎→灰、精神攻撃→魂魄 など）
- 死体状態が悪いほど: 蘇生費用が跳ね上がる / 必要な術者・施設の格が上がる / 失敗リスクや後遺症の可能性

**蘇生の手段（確定事項）**

| 手段 | 条件 | 費用感 |
|---|---|---|
| 地上の蘇生施設 | **ゲーム開始時から利用可**。操作フェイズ中に実行。死体等が手元にあること | **割高**。誰でも頼れる標準の受け皿 |
| 自前の回復術師（地上） | 蘇生可能な回復術を使える**生存中の**メンバーがいること | **割安**。術者の格が扱える死体状態の上限を決める |
| ダンジョン内での蘇生 | 強力な回復術師がそのパーティに同行していること | その場で復帰できるが、術者の格と死体状態による制限が大きい |

- 「高いが常に頼れる施設」と「安いが人材依存の自前蘇生」の2本立て。
  蘇生術師を雇い維持すること自体が投資判断になる（その術師が死ぬと施設頼みに戻る）

**全滅時の扱い**

生還者がいないため死体は現地に残される。回収手段は2系統：

1. **救出・回収任務**: 別パーティを編成して現地へ派遣する（依頼類型のひとつとして実装）。
   日数が経つほど死体の状態が悪化するため、急ぐか、諦めて後で高コスト蘇生するかの判断になる
2. **降霊術**: 大金を払って魂を呼び、魂魄状態からの蘇生を行う。死体回収は不要だが最高コスト帯

- 全滅は「取り返しのつかない失敗」ではなく「**巨額の出費と時間を要する経営危機**」として設計する。
  倒産（§2.3）に至る主要因のひとつになる想定

## 4. パーティと派遣

### 4.0 派遣は「送り出したら全自動」（確定事項）

- **派遣後のパーティには一切の追加指示を出せない。帰還（または全滅）まで全自動で進行する**
- 道中の遭遇・トラブルもすべて自動解決され、プレイヤーは日次のイベントログで経過を知るのみ
- したがって、プレイヤーの意思決定はすべて**派遣前**に集約される：
  - 誰を何人送るか（編成）
  - 食料・装備をどれだけ持たせるか（補給）
  - **行動方針**の指定（例: 慎重＝危険を察知したら撤退優先 / 標準 / 強行＝多少の損害でも任務継続）
- 行動方針は自動解決時の判断基準（撤退ライン・遭遇時の対応傾向）として機能する。
  MVPでは3段階のプリセットで十分。細かな条件指定（「負傷者2名で撤退」等）は拡張候補
- この仕様の狙い: 「見送ったあとは祈るだけ」の緊張感と、帰還報告を開ける楽しみ。
  経営ゲームとしての判断密度を編成画面に集中させる

### 4.1 人数の設計方針

- **システム上の最大: 20人／依頼**（UI・処理はこれを前提に設計する）
- **「多いほど良い」にはしない。ただし一律のペナルティで最適人数を固定もしない。**
  複数の独立したコスト系統を用意し、依頼の性質によって効いてくるコストが変わるようにする。
  → 「この依頼なら大所帯で圧殺」「この依頼は精鋭3人」「これは戦力2人＋荷物持ち6人」が
  それぞれ正解になり得る状態が設計目標

### 4.2 人数のメリット

- 各判定に参加できる頭数（総合力・役割分担・並行作業）
- 総運搬力の増加 → 回収品報酬の増加
- 冗長性: 負傷者が出ても任務を継続できる

### 4.3 人数のコスト（複数系統）

| 系統 | 内容 | 効きやすい依頼 |
|---|---|---|
| **経済** | 報酬は参加者に分配される（§6）ため、頭数を送るほどギルドの取り分率が下がる。食料・遠征経費も人数×日数で増加 | すべて（常時の圧力） |
| **隠密・遭遇** | 大所帯は目立つ。遭遇危険度が人数で上昇し、**縄張りの主クラスの凶悪モンスター**を引きやすくなる | ダンジョン・魔物領域の依頼 |
| **補給** | 消費食料 = 人数×日数。食料は運搬力を圧迫し、**積んだ分だけ戦利品を持ち帰れない** | 長期・遠方の依頼 |
| **依頼側の制約** | 潜入・護衛は人数上限、儀式妨害は少数のみ、逆に大規模討伐は人数下限あり | 依頼による |
| **統率** | 一定人数を超えると指揮スキルがないと士気・判定にペナルティ（烏合の衆化） | 大所帯全般 |

**遭遇危険度（方針確定）**:

- 遭遇は全自動で解決される（§4.0）ため、**人数増による遭遇「頻度」の上昇はマイルドで良い**
  （多少戦闘が頻繁になっても操作負担は増えない）。大所帯を実際に締めるのは
  **遭遇の「質」＝主（ボス）クラスとの遭遇率**と、頭割り分配による経済圧力とする
- 斥候を入れれば大所帯でも頻度をある程度緩和できる（＝編成で解決できる問題にする）が、
  緩和には上限を設け「20人で隠密潜入」は成立させない
- 具体式と係数は §12.4

### 4.4 運搬力と補給

- 各メンバーは運搬力を持つ（筋力＋運搬スキル＋装備で決まる）
- パーティ総運搬力から食料・装備の重量を引いた残りが**回収可能量**
- 回収品（素材・遺物・鉱石）は持ち帰った分だけ換金・納品できる
  → 「たくさん回収したいから荷物持ちを連れて行く」が数値上で成立する

## 5. 依頼（クエスト）

### 5.1 依頼の構造

依頼は単一の要求値ではなく、**課題（チェック）のリスト**を持つ。

| 項目 | 内容 |
|---|---|
| 課題リスト | 例:「戦闘脅威 30」「罠 10」「古代語解読 15」「採掘量目標 200」など複数 |
| 経路情報 | 距離（所要日数）、経路の危険度、環境タグ（暗所・山岳・水場…） |
| 人数条件 | 上限・下限・推奨（ない依頼も多い） |
| 期限 | 受注しないまま n 日で掲示板から消滅 |
| 報酬 | 固定報酬（資金＋名声）＋ **変動報酬（回収品の量・調査成果の品質に応じる）** |
| 失敗時 | 違約金 + 名声低下 + 派遣メンバーの負傷判定 |

### 5.2 依頼の例（編成の多様性を生む見本）

- **地下遺跡の学術調査**: 課題=[護衛戦闘, 罠, 古代語解読]。学者必須級。成果品質は学術系スキル依存。
  人数を増やすと遺跡の主を起こすリスク（隠密系コストが支配的）
- **鉱山の採掘請負**: 課題=[採掘量目標, 軽微な魔物]。採掘師の頭数と運搬力が物を言う。
  大所帯が正解になりやすいが、給料と食料で利益率との勝負（経済・補給コストが支配的）
- **要人の隠密護送**: 課題=[戦闘, 隠密経路]。人数上限4。少数精鋭でしか受けられない
- **森の大討伐**: 課題=[戦闘 大]。人数下限8。頭数と指揮スキルが必要

### 5.3 課題への人数寄与 — 課題ごとの集計型（確定事項）

課題判定に使う「パーティ該当能力」の算出方法は全課題一律にしない。
単純な全員合算では「平凡な20人が精鋭4人に必ず勝つ」ことになり頭数一辺倒に戻るため、
**課題ごとに集計型を持たせる**。集計型は4種類：

| 集計型 | 算出方法 | 適用する課題の例 | 人数の効き方 |
|---|---|---|---|
| **加算型** | 該当スキル持ち全員の単純合算 | 採掘量、採取、運搬 | 頭数が素直に効く。経済・補給コストとの勝負 |
| **席数型** | 上位 N 人（席数）のみ寄与。**席数は課題側・環境で決まる** | 戦闘（狭い洞窟=4席、平原の大討伐=12席）、罠処理（2席） | 席数までは増員が有効、超過分は無意味 |
| **代表型** | 最高値の1人が基準。2人目以降はわずかな補助ボーナスのみ | 古代語解読、鑑定、交渉 | 専門家1人の質がすべて。数は不要 |
| **最弱連動型** | **最低値の1人**が基準＋人数ペナルティ | 隠密行動 | 増員するほど不利。少数精鋭が必須 |

- 集計型と席数は依頼データ側で定義する（データ駆動）。同じ「戦闘」でも環境タグで席数が変わる
- この仕組みにより「洞窟遺跡の調査＝戦闘4席＋学者1人＋残りは荷物持ちが有効、
  それ以上の増員はコストだけ増える」といった**依頼ごとの適正人数・適正構成**が
  依頼データから自然に導かれる

### 5.4 成否判定（初版案）

- 課題ごとに、§5.3 の集計型で算出したパーティ該当能力と課題値から成功率を算出。
  **差分式ではなく比率式**を採用する（能力のスケールが変わるE帯〜S帯で係数の再調整が不要になるため）:

```
課題成功率 = clamp(50% + 50% × (R − 1), 5%, 95%)   ただし R = パーティ該当能力 ÷ 課題値
```

- 目安: 課題値ちょうど（R=1.0）で50%、1.5倍で75%、1.8倍で90%。
  適正編成の想定は R≈1.5〜1.8

- 全課題の結果から総合成果を段階評価（大成功 / 成功 / 部分成功 / 失敗）
- 回収量・調査品質は成果段階と残り運搬力・専門スキルで決まる
- 道中の遭遇は §4.3 の遭遇危険度で別途発生し、負傷・食料損失・撤退などをもたらす。
  遭遇の解決は**全自動**（§4.0）。行動方針と斥候・戦力から回避/戦闘/撤退が自動選択される
- 過剰戦力なら安全だが利益率が悪く、ギリギリなら効率的だがリスクが高い、という
  **経営判断のジレンマ**を全系統で維持する。係数は要バランス調整

## 6. 経済

- 通貨は1種類（ゴールド）
- **収入**: 依頼の固定報酬、回収品の換金、（拡張: 施設収入）
- **支出**: 冒険者への報酬分配・基本給、食料・遠征経費（派遣時）、施設維持費、雇用一時金、違約金、蘇生費
- 毎ターン終了時に収支を精算。赤字が続くと倒産リスク
- 画面に常に「残高」「1ターンあたりの固定費」を表示し、収支感覚を持たせる

### 6.1 給与体系（方針確定）

**報酬分配が主、継続的な基本給は副次的**という配分にする。

- **報酬分配**: 依頼で得た報酬（固定報酬＋回収品の換金額）の一定割合を、
  その依頼の参加メンバーに分配する。冒険者の主収入はこちら
- **基本給**: 毎ターン少額を全所属メンバーに支払う（拘束料・生活保障のイメージ）
- **死亡中も基本給は支払う**。蘇生費を惜しんで放置しても維持費はかかり続ける。
  見込みがなければ死亡中に解雇して損切りしてもよい（その場合のみロスト）

この体系の狙い:

- 「抱える」のは比較的安く、「動かす」と取り分が割れる
  → 大所帯ギルド自体は成立するが、**1件の依頼に何人送るかが損益に直結**する（§4.3 経済系統の実体）
- 稼げない依頼に人を出すと分配で赤字になり得る一方、待機させ続けても基本給で薄く出血する
  → 手持ち人材の稼働率が経営指標になる

**分配方式: 頭割り（確定事項）**

- 依頼報酬のうち冒険者への分配分を、参加メンバーで均等に頭割りする
- 能力・貢献度比例に**しない**理由: 強いキャラほど取り分が増える方式だと
  「キャラを成長させると人件費が上がる＝育てたくない」という逆インセンティブが生まれるため。
  シミュレーションとしての面白みより面倒さが勝つと判断（設計判断として記録しておく）
- 失敗時は「得た報酬」がないため分配も発生しない。違約金はギルドが負担する
  （冒険者は命懸けで働いて無収入、ギルドは違約金——失敗はお互いに痛い）
- 留意点: 頭割りのため、キャラの強さは分配額に反映されない。**優秀な人材の対価は
  雇用一時金と基本給の傾斜（応募時の能力に応じて決まり、成長では上がらない）で表現する**。
  こうすれば「育てるほど得」が保たれる。具体的な傾斜は数値バランスで決める

## 7. 施設（投資先）

| 施設 | 効果（初版案) |
|---|---|
| 訓練所 | 待機中の冒険者が少しずつ経験値を得る |
| 医務室 | 負傷の回復日数を短縮 |
| 酒場 | 応募者の質・数が向上（珍しい職も来やすく） |
| 受付拡張 | 同時受注数 +1 |
| 倉庫 | 回収品の保管量増・相場を見て売るなど（拡張寄り） |

各施設はレベル制（Lv1〜3）。建設費＋毎ターン維持費。

## 8. 名声とギルドランク

- 依頼の成功で名声が増え、失敗で減る。成果段階（大成功等）で増分が変わる
- 名声の累計でギルドランクが E → D → … → S と昇格
- ランクが上がると: 高難度依頼が届く / 同時受注数が増える / 良い応募者が来る

## 9. 画面構成（ブラウザ / 初版）

SPA・1画面ベース。タブまたはペインで切り替え：

1. **メイン（ギルド）**: 残高・名声・ランク・日付、今日のイベントログ、「日を進める」ボタン
2. **依頼掲示板**: 依頼一覧（課題・経路・人数条件・報酬・期限）、受注操作
3. **冒険者一覧**: 所属メンバーの能力・スキル・特性・状態、応募者の雇用
4. **派遣編成**: 受注済み依頼へのパーティ編成・補給・行動方針の設定。**編成画面が本作の主戦場**
   （派遣後は指示不可のため、意思決定はすべてここに集約される）。
   課題ごとの成功率見込み（席の埋まり具合・無駄人員も見える形で）・遭遇危険度・
   利益見込み（報酬 − 人件費 − 食料）・運搬力の残りをリアルタイムに表示し、
   人数と構成の試行錯誤を快適にする
5. **施設**: 建設・アップグレード

**帰還報告（方向性のみ確定、詳細は後日）**

- 帰還時のリザルトは**概要1枚**（成否・報酬・負傷/死亡・回収品のサマリ）をまず表示し、
  詳細（道中の遭遇ログ、課題ごとの判定内訳など）はクリック/タップ/キー操作で
  ドリルダウンして見られる2層構造とする
- 全自動派遣（§4.0）ゆえに帰還報告は体験の山場。ログの粒度・演出は他のシステムが
  固まってから詰める

グラフィックは初版ではテキスト＋簡易UIで十分（数値管理ゲームなので情報の見やすさを優先）。

## 10. 技術方針

- **プラットフォーム**: ブラウザ（Web技術）
- 想定スタック: TypeScript + 軽量フレームワーク（React or Svelte、要決定）+ Vite
- サーバ不要の完全クライアント動作。セーブは `localStorage`（JSON1本のステート）
- ゲームロジックはUIから分離した純粋関数群にする（テストとバランス調整シミュレーションが容易になるため）
- 乱数はシード指定可能にする（テスト・デバッグ用）
- 判定式・遭遇テーブルはデータ駆動にし、バランス調整をコード変更なしで回せるようにする

## 11. スコープ定義

### MVP（最初に作る範囲）

- ターン進行（1日単位）と収支精算
- キャラクター: 能力値6種＋スキル10種程度＋特性数個。職業肩書き 6種（戦士/斥候/学者/荷物持ち/採掘師/治癒師）
- パーティ: **最大人数は最初から20人対応**（後から上げるとUI・バランスを作り直しになるため）。
  人数コストは「経済」「補給・運搬」「遭遇」の3系統をまず実装（統率は後回し）
- 派遣は全自動解決。行動方針は3段階プリセット（慎重/標準/強行）
- 依頼: 課題リスト式・集計型4種（加算/席数/代表/最弱連動）を最初から実装。
  討伐 / 遺跡調査 / 採掘 / 護送 の4類型、難易度E〜C
- 遭遇イベント: 危険度→遭遇表のシンプルな実装（負傷・食料損失・撤退・死亡）
- 状態異常ラダー: 健康/軽傷/重傷＋死体3段階（健全/損傷/白骨）の6段階に簡略化。
  地上施設での蘇生（割高）と自前術者による割引、全滅時の降霊術（大金）を実装。
  **救出任務・ダンジョン内蘇生・灰以降の死体状態はMVP外**
- 給与: 報酬分配（頭割り）＋基本給。死亡中の基本給支払いと損切り解雇も実装
- 帰還報告: 概要1枚＋詳細ドリルダウンの2層構造（演出は最小限）
- 施設: 2種類（受付拡張・医務室）
- 敗北条件（倒産）と ランクE→C までの昇格
- localStorage セーブ / ロード

### MVP に入れないもの（拡張候補）

- 救出・回収任務、ダンジョン内蘇生、死体状態の下位段階（灰・魂魄・魂の破片）
- 統率・士気システム、特性の相互作用（人間関係）
- 冒険者の引退ドラマ、性格によるイベント
- ランダムイベント（依頼の裏切り、盗賊の襲撃、王都からの特命など）
- 回収品の相場変動・倉庫運用
- 競合ギルド・依頼の取り合い
- 難易度B〜S帯のコンテンツとバランス
- 音・グラフィック演出

## 12. プレイ時間と数値バランス初期値（たたき台）

### 12.1 1プレイの尺（確定事項）

- **クリア（ギルドランクS到達）まで実時間 約2〜3時間**を目標とする。
  フリーゲームとして「一晩〜週末で遊び切れて、全システム（大所帯運用・蘇生・施設）が
  回りきる」長さとしてこの線を採る
- 1ターンの操作時間を平均約1分（編成する日30〜90秒、送り出すだけの日は数秒）と見て、
  **クリアまで約120〜150ターン**に相当
- MVP範囲（ランクE→C）はその前半、**約60ターン・1時間弱**を想定
- ランク昇格の名声しきい値・依頼供給はこのターン数から逆算して調整する

### 12.3 検証方法と結果

- `tools/balance_sim.py`: 上記の値で「損得を考えず順に受注し続ける無策プレイ」を
  60日×100シード試行するスクリプト（Python、依存なし）
- 結果: 倒産率 11% / 最終資金の中央値 約1,750G（初期1,500Gから微増基調）/
  下位10%は資金ゼロ付近まで落ち込む
- 狙い: **普通に遊べば緩やかに成長し、連続失敗や蘇生費の一撃で倒産が現実的に見える**バランス。
  無策プレイの倒産率は10%前後を維持目標とし、数値を動かしたらこのスクリプトで回帰確認する
- 未検証: B〜S帯の報酬カーブ、施設効果の費用対効果

### 12.4 判定・遭遇の初期係数（たたき台）

`tools/encounter_sim.py` で検証済み。個人の課題能力 = 関連能力値 + 関連スキルLv×2
（序盤の平均像 ≈ 13）を基準スケールとする。

**判定（§5.4 の比率式）**: R = パーティ該当能力 ÷ 課題値、成功率 = clamp(50% + 50%×(R−1), 5%, 95%)

**遭遇**:

```
日次遭遇率     = 経路危険度 × (1 + 0.05 × (人数 − 4)) × (1 − 斥候軽減)
斥候軽減       = min(60%, 最良斥候の斥候スキルLv × 6%)      … 代表型
主クラス遭遇率 = min(35%, 5% + 1.5% × (人数 − 4))           … 遭遇発生時の内訳
主クラス敵戦力 = 通常敵の2.5倍
```

| 経路危険度 | 値（1日あたり基礎遭遇率） |
|---|---|
| 安全（街道・近郊） | 10% |
| 並（森・丘陵） | 20% |
| 危険（魔物領域） | 35% |
| 魔境（B帯以上で使用） | 50% |

- 遭遇も §5.4 と同じ比率式で解決（パーティ戦闘力[席数型] vs 敵戦力）。
  敗北時は負傷・死亡判定のうえ任務中断（＝依頼失敗）
- **通常敵は適正編成なら安定して勝てる強さ**（敵戦力 ≈ 戦闘課題値の0.75倍目安）に設定し、
  消耗を与える役に留める。**大所帯の実リスクは主クラス遭遇率の上昇**に集約させる
  （人数で頻度はマイルドにしか増やさない。§4.3 の確定方針）

**検証結果（人数を2〜20人で振った場合の期待利益ピークと死者率）**:

| 依頼 | 適正人数（利益ピーク） | ピーク時: 成功率/利益 | 20人時: 利益/死者率 |
|---|---|---|---|
| E討伐（安全・席4） | 3人 | 94% / +97G | −153G / 1.5人per100件 |
| D討伐（並・席4） | 4人 | 75% / +94G | −314G / 6.3 |
| C採掘（並・席4・加算型） | **10人** | 83% / +174G | −311G / 9.4 |
| C討伐（危険・席6） | 6人 | 68% / +115G | −520G / 13.9 |

- 依頼ごとに異なる適正人数がデータ側から生まれること（§4.1 の設計目標）、
  少人数は成功率・死者率で、過剰人数は分配と主クラス遭遇で罰されることを確認済み
