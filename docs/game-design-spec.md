# 冒険者ギルド運営シミュレーション 仕様書

- 版数: 0.2（ドラフト）
- 最終更新: 2026-07-12
- ステータス: コンセプト・コアループ確定 / パーティ・キャラクターシステムの方針確定 / 数値詳細は検討中

## 1. コンセプト

> プレイヤーは辺境の町の**ギルドマスター**。冒険者を雇い、舞い込む依頼に派遣し、
> 報酬をやりくりしてギルドを設備投資・人材で強化していく、**ターン制の経営シミュレーション**。

- 一番の楽しさ（コア体験）: **経営・数値管理**、とりわけ**編成パズル**
  - 「どの依頼を受け、**誰を何人**送り、何に投資するか」を毎ターン判断する意思決定の手応え
  - リスク（依頼の失敗・冒険者の負傷）とリターン（報酬・名声）の天秤
- 冒険者は多彩な能力を持つ「経営資源」。戦闘職だけでなく**非戦闘職**（荷物持ち・学者・採掘師など）が
  依頼によっては主役になる
- **普遍的な最適解（最強編成・最適人数）は存在させない**。依頼の内容・経路・目的と手持ちの
  人材の噛み合わせで、毎回考える必要がある状態を目指す

## 2. ゲームの基本構造

### 2.1 進行形式

- **ターン制。1ターン = 1日**
- ターン中はプレイヤーの操作フェイズ（受注・編成・投資）→「日を進める」で解決フェイズ
- リアルタイム要素・放置要素は入れない

### 2.2 コアループ

```
① 依頼が掲示板に届く（毎朝、数件が追加・古いものは期限切れ）
        ↓
② 受注する依頼を選ぶ（同時進行数はギルドランクで制限）
        ↓
③ パーティを編成して派遣（人数・構成・補給が成果とコストを左右する）
        ↓
④ 日を進める → 派遣中の依頼が進行、道中の遭遇イベント、完了日に成果判定
        ↓
⑤ 報酬・名声・回収品を獲得（失敗なら違約金・負傷）
        ↓
⑥ 収入で 雇用 / 施設投資 / 装備支援 → より難しい依頼が受けられるように → ①へ
```

### 2.3 勝敗・ゲームの終わり

- **敗北条件**: 資金がマイナスのままターン終了時の支払い（給料・維持費）ができない → 倒産
- **勝利条件（初版）**: ギルドランクを最高位（S）まで上げる
- クリア後はフリープレイ継続可

## 3. キャラクターシステム

### 3.1 能力の3層構造

キャラクターは「能力値 × スキル × 特性」の3層で表現する。
職業（クラス）は固定の枠ではなく、**スキル構成に付いた肩書き**として扱う（応募者の分かりやすさのため）。

**① 基礎能力値（6種、1〜20）**

| 能力値 | 主な用途 |
|---|---|
| 筋力 | 近接戦闘、運搬量 |
| 耐久 | 生存性、負傷しにくさ、長期任務への耐性 |
| 器用 | 罠解除、採掘・工作、射撃 |
| 知力 | 学術調査、鑑定、魔法 |
| 感知 | 索敵、危険察知、隠密 |
| 魅力 | 交渉、士気、護衛対象の受け |

**② スキル（Lv0〜10、能力値と組み合わせて判定に使う）**

| 系統 | 例 |
|---|---|
| 戦闘系 | 剣術、弓術、攻撃魔法、盾防御 |
| 探索系 | 斥候・隠密、罠解除、追跡、地図作成 |
| 学術系 | 考古学・古代語、鑑定、薬学 |
| 技能系 | 採掘、採取、運搬、料理、応急手当、鍛冶 |
| 対人系 | 交渉、指揮、荷役管理 |

**③ 特性（トレイト。パッシブな個性）**

例: 夜目（暗所ペナルティ無効）、頑健（負傷日数短縮）、大食い（補給消費+50%）、
臆病（凶悪遭遇時に離脱判定）、カリスマ（同行者の士気+）など。
プラスとマイナスの両方を持たせ、給料と釣り合わせる。

### 3.2 職業（肩書き）の例

応募者は肩書き付きで現れるが、実体はスキルセット。育成次第で複合職化も可能。

- **戦闘職**: 戦士、弓手、魔導士、盾持ち
- **探索職**: 斥候、罠師、狩人
- **非戦闘職**: **荷物持ち**（運搬特化・回収量を増やす）、**学者**（遺跡調査の成果品質を上げる）、
  **採掘師**（採掘依頼の主役）、治癒師、料理人（長期任務の補給効率・士気）、交渉人

### 3.3 その他

- 状態: 待機 / 派遣中 / 負傷（n日間派遣不可）
- 給料: 毎ターン支払い。未払いは士気低下→離脱
- 成長: 依頼で実際に使ったスキルに経験が入る（使った能力が伸びる）
- 雇用は「応募者リスト」から。名声が高いほど良い人材・珍しい職が応募してくる

## 4. パーティと派遣

### 4.1 人数の設計方針

- **システム上の最大: 20人／依頼**（UI・処理はこれを前提に設計する）
- **「多いほど良い」にはしない。ただし一律のペナルティで最適人数を固定もしない。**
  複数の独立したコスト系統を用意し、依頼の性質によって効いてくるコストが変わるようにする。
  → 「この依頼なら大所帯で圧殺」「この依頼は精鋭3人」「これは戦力2人＋荷物持ち6人」が
  それぞれ正解になり得る状態が設計目標

### 4.2 人数のメリット

- 各判定に参加できる頭数（総合力・役割分担・並行作業）
- 総運搬力の増加 → 回収品報酬の増加
- 冗長性: 負傷者が出ても任務を継続できる

### 4.3 人数のコスト（複数系統）

| 系統 | 内容 | 効きやすい依頼 |
|---|---|---|
| **経済** | 給料・遠征手当が人数×日数で増加。報酬は固定なので利益率が下がる | すべて（常時の圧力） |
| **隠密・遭遇** | 大所帯は目立つ。遭遇危険度が人数で上昇し、**縄張りの主クラスの凶悪モンスター**を引きやすくなる | ダンジョン・魔物領域の依頼 |
| **補給** | 消費食料 = 人数×日数。食料は運搬力を圧迫し、**積んだ分だけ戦利品を持ち帰れない** | 長期・遠方の依頼 |
| **依頼側の制約** | 潜入・護衛は人数上限、儀式妨害は少数のみ、逆に大規模討伐は人数下限あり | 依頼による |
| **統率** | 一定人数を超えると指揮スキルがないと士気・判定にペナルティ（烏合の衆化） | 大所帯全般 |

**遭遇危険度（初版の考え方）**:

```
遭遇危険度 = 経路の危険度 × 人数係数(人数に応じて上昇) − 斥候・隠密の軽減
遭遇の「質」も危険度に連動（高いと上位モンスター遭遇表を引く）
```

- 斥候を入れれば大所帯でもある程度緩和できる（＝編成で解決できる問題にする）が、
  緩和には上限を設け「20人で隠密潜入」は成立させない

### 4.4 運搬力と補給

- 各メンバーは運搬力を持つ（筋力＋運搬スキル＋装備で決まる）
- パーティ総運搬力から食料・装備の重量を引いた残りが**回収可能量**
- 回収品（素材・遺物・鉱石）は持ち帰った分だけ換金・納品できる
  → 「たくさん回収したいから荷物持ちを連れて行く」が数値上で成立する

## 5. 依頼（クエスト）

### 5.1 依頼の構造

依頼は単一の要求値ではなく、**課題（チェック）のリスト**を持つ。

| 項目 | 内容 |
|---|---|
| 課題リスト | 例:「戦闘脅威 30」「罠 10」「古代語解読 15」「採掘量目標 200」など複数 |
| 経路情報 | 距離（所要日数）、経路の危険度、環境タグ（暗所・山岳・水場…） |
| 人数条件 | 上限・下限・推奨（ない依頼も多い） |
| 期限 | 受注しないまま n 日で掲示板から消滅 |
| 報酬 | 固定報酬（資金＋名声）＋ **変動報酬（回収品の量・調査成果の品質に応じる）** |
| 失敗時 | 違約金 + 名声低下 + 派遣メンバーの負傷判定 |

### 5.2 依頼の例（編成の多様性を生む見本）

- **地下遺跡の学術調査**: 課題=[護衛戦闘, 罠, 古代語解読]。学者必須級。成果品質は学術系スキル依存。
  人数を増やすと遺跡の主を起こすリスク（隠密系コストが支配的）
- **鉱山の採掘請負**: 課題=[採掘量目標, 軽微な魔物]。採掘師の頭数と運搬力が物を言う。
  大所帯が正解になりやすいが、給料と食料で利益率との勝負（経済・補給コストが支配的）
- **要人の隠密護送**: 課題=[戦闘, 隠密経路]。人数上限4。少数精鋭でしか受けられない
- **森の大討伐**: 課題=[戦闘 大]。人数下限8。頭数と指揮スキルが必要

### 5.3 成否判定（初版案）

- 課題ごとに、対応するパーティ能力（該当スキル持ちの合算。ただし人数寄与は逓減）と課題値から成功率を算出:

```
課題成功率 = clamp(基準50% + (パーティ該当能力 − 課題値) × 係数, 5%, 95%)
```

- 全課題の結果から総合成果を段階評価（大成功 / 成功 / 部分成功 / 失敗）
- 回収量・調査品質は成果段階と残り運搬力・専門スキルで決まる
- 道中の遭遇は §4.3 の遭遇危険度で別途発生し、負傷・食料損失・撤退などをもたらす
- 過剰戦力なら安全だが利益率が悪く、ギリギリなら効率的だがリスクが高い、という
  **経営判断のジレンマ**を全系統で維持する。係数は要バランス調整

## 6. 経済

- 通貨は1種類（ゴールド）
- **収入**: 依頼の固定報酬、回収品の換金、（拡張: 施設収入）
- **支出**: 給料（毎ターン）、遠征手当・食料（派遣時）、施設維持費、雇用一時金、違約金
- 毎ターン終了時に収支を精算。赤字が続くと倒産リスク
- 画面に常に「残高」「1ターンあたりの固定費」を表示し、収支感覚を持たせる
- 大所帯ギルドは固定費（給料総額）が重い。**抱える人数自体が経営判断**になる

## 7. 施設（投資先）

| 施設 | 効果（初版案) |
|---|---|
| 訓練所 | 待機中の冒険者が少しずつ経験値を得る |
| 医務室 | 負傷の回復日数を短縮 |
| 酒場 | 応募者の質・数が向上（珍しい職も来やすく） |
| 受付拡張 | 同時受注数 +1 |
| 倉庫 | 回収品の保管量増・相場を見て売るなど（拡張寄り） |

各施設はレベル制（Lv1〜3）。建設費＋毎ターン維持費。

## 8. 名声とギルドランク

- 依頼の成功で名声が増え、失敗で減る。成果段階（大成功等）で増分が変わる
- 名声の累計でギルドランクが E → D → … → S と昇格
- ランクが上がると: 高難度依頼が届く / 同時受注数が増える / 良い応募者が来る

## 9. 画面構成（ブラウザ / 初版）

SPA・1画面ベース。タブまたはペインで切り替え：

1. **メイン（ギルド）**: 残高・名声・ランク・日付、今日のイベントログ、「日を進める」ボタン
2. **依頼掲示板**: 依頼一覧（課題・経路・人数条件・報酬・期限）、受注操作
3. **冒険者一覧**: 所属メンバーの能力・スキル・特性・状態、応募者の雇用
4. **派遣編成**: 受注済み依頼へのパーティ編成。**編成画面が本作の主戦場**。
   課題ごとの成功率見込み・遭遇危険度・利益見込み（報酬 − 人件費 − 食料）・運搬力の残りを
   リアルタイムに表示し、人数と構成の試行錯誤を快適にする
5. **施設**: 建設・アップグレード

グラフィックは初版ではテキスト＋簡易UIで十分（数値管理ゲームなので情報の見やすさを優先）。

## 10. 技術方針

- **プラットフォーム**: ブラウザ（Web技術）
- 想定スタック: TypeScript + 軽量フレームワーク（React or Svelte、要決定）+ Vite
- サーバ不要の完全クライアント動作。セーブは `localStorage`（JSON1本のステート）
- ゲームロジックはUIから分離した純粋関数群にする（テストとバランス調整シミュレーションが容易になるため）
- 乱数はシード指定可能にする（テスト・デバッグ用）
- 判定式・遭遇テーブルはデータ駆動にし、バランス調整をコード変更なしで回せるようにする

## 11. スコープ定義

### MVP（最初に作る範囲）

- ターン進行（1日単位）と収支精算
- キャラクター: 能力値6種＋スキル10種程度＋特性数個。職業肩書き 6種（戦士/斥候/学者/荷物持ち/採掘師/治癒師）
- パーティ: **最大人数は最初から20人対応**（後から上げるとUI・バランスを作り直しになるため）。
  人数コストは「経済」「補給・運搬」「遭遇」の3系統をまず実装（統率は後回し）
- 依頼: 課題リスト式。討伐 / 遺跡調査 / 採掘 / 護送 の4類型、難易度E〜C
- 遭遇イベント: 危険度→遭遇表のシンプルな実装（負傷・食料損失・撤退）
- 施設: 2種類（受付拡張・医務室）
- 敗北条件（倒産）と ランクE→C までの昇格
- localStorage セーブ / ロード

### MVP に入れないもの（拡張候補）

- 統率・士気システム、特性の相互作用（人間関係）
- 冒険者の引退/死亡ドラマ、性格によるイベント
- ランダムイベント（依頼の裏切り、盗賊の襲撃、王都からの特命など）
- 回収品の相場変動・倉庫運用
- 競合ギルド・依頼の取り合い
- 難易度B〜S帯のコンテンツとバランス
- 音・グラフィック演出
