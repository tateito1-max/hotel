# 冒険者ギルド運営シミュレーション 仕様書（初版）

- 版数: 0.1（ドラフト）
- 最終更新: 2026-07-11
- ステータス: コンセプト・コアループ確定 / 詳細仕様は検討中

## 1. コンセプト

> プレイヤーは辺境の町の**ギルドマスター**。冒険者を雇い、舞い込む依頼に派遣し、
> 報酬をやりくりしてギルドを設備投資・人材で強化していく、**ターン制の経営シミュレーション**。

- 一番の楽しさ（コア体験）: **経営・数値管理**
  - 限られた資金と人材で「どの依頼を受け、誰を送り、何に投資するか」を毎ターン判断する意思決定の手応え
  - リスク（依頼の失敗・冒険者の負傷）とリターン（報酬・名声）の天秤
- 冒険者はキャラクターというより「能力と維持費を持つ経営資源」として扱う
  （個別のドラマ・育成劇は将来拡張とし、初版では深追いしない）

## 2. ゲームの基本構造

### 2.1 進行形式

- **ターン制。1ターン = 1日**
- ターン中はプレイヤーの操作フェイズ（受注・編成・投資）→「日を進める」で解決フェイズ
- リアルタイム要素・放置要素は入れない

### 2.2 コアループ

```
① 依頼が掲示板に届く（毎朝、数件が追加・古いものは期限切れ）
        ↓
② 受注する依頼を選ぶ（同時進行数はギルドランクで制限）
        ↓
③ 冒険者を編成して派遣（依頼ごとに所要日数がある）
        ↓
④ 日を進める → 派遣中の依頼が進行、完了日に成否判定
        ↓
⑤ 報酬・名声を獲得（失敗なら違約金・負傷）
        ↓
⑥ 収入で 雇用 / 施設投資 / 装備支援 → より難しい依頼が受けられるように → ①へ
```

### 2.3 勝敗・ゲームの終わり

- **敗北条件**: 資金がマイナスのままターン終了時の支払い（給料・維持費）ができない → 倒産
- **勝利条件（初版）**: ギルドランクを最高位（S）まで上げる
- クリア後はフリープレイ継続可

## 3. 主要システム

### 3.1 冒険者

| 項目 | 内容 |
|---|---|
| 基本ステータス | 戦闘力 / 探索力 / 交渉力 の3値（依頼の要求値と対応） |
| ランク | E〜S。雇用費・給料の目安 |
| 状態 | 待機 / 派遣中 / 負傷（n日間派遣不可） |
| 給料 | 毎ターン支払い。未払いは士気低下→離脱 |
| 成長 | 依頼達成で経験値、一定でステータス上昇（シンプルなレベル制） |

- 雇用は「応募者リスト」から。ギルドの名声が高いほど良い人材が応募してくる
- 初版では性格・スキル・人間関係は**入れない**（拡張候補）

### 3.2 依頼（クエスト）

| 項目 | 内容 |
|---|---|
| 種別 | 討伐（戦闘力）/ 探索（探索力）/ 商談・護衛（交渉力）など、要求ステータスが異なる |
| 難易度 | E〜S。要求値と報酬が連動 |
| 所要日数 | 1〜7日程度 |
| 期限 | 受注しないまま n 日で掲示板から消滅 |
| 報酬 | 資金 + 名声 |
| 失敗時 | 違約金 + 名声低下 + 派遣メンバーの負傷判定 |

**成否判定（初版案）**:
派遣パーティの合計該当ステータス vs 依頼の要求値で成功率を算出し、乱数で判定。

```
成功率 = clamp(基準50% + (パーティ合計値 - 要求値) × 係数, 5%, 95%)
```

- 過剰戦力なら安全だが報酬効率が悪く、ギリギリ戦力なら効率的だがリスクが高い、
  という**経営判断のジレンマ**を作るのがこの式の目的。係数は要バランス調整

### 3.3 経済

- 通貨は1種類（ゴールド）
- **収入**: 依頼報酬、（拡張: 酒場などの施設収入）
- **支出**: 冒険者の給料（毎ターン）、施設の維持費、雇用一時金、違約金
- 毎ターン終了時に収支を精算。赤字が続くと倒産リスク
- 画面に常に「今の残高」と「1ターンあたりの固定費」を表示し、収支感覚を持たせる

### 3.4 施設（投資先）

| 施設 | 効果（初版案） |
|---|---|
| 訓練所 | 待機中の冒険者が少しずつ経験値を得る |
| 医務室 | 負傷の回復日数を短縮 |
| 酒場 | 応募者の質・数が向上 |
| 受付拡張 | 同時受注数 +1 |

各施設はレベル制（Lv1〜3）。建設費＋毎ターン維持費。

### 3.5 名声とギルドランク

- 依頼の成功で名声が増え、失敗で減る
- 名声の累計でギルドランクが E → D → … → S と昇格
- ランクが上がると: 高難度依頼が届く / 同時受注数が増える / 良い応募者が来る

## 4. 画面構成（ブラウザ / 初版）

SPA・1画面ベース。タブまたはペインで切り替え：

1. **メイン（ギルド）**: 残高・名声・ランク・日付、今日のイベントログ、「日を進める」ボタン
2. **依頼掲示板**: 依頼一覧（要求値・報酬・期限）、受注操作
3. **冒険者一覧**: 所属メンバーの状態・ステータス、応募者の雇用
4. **派遣編成**: 受注済み依頼に冒険者を割り当てる（成功率の見込みを表示）
5. **施設**: 建設・アップグレード

グラフィックは初版ではテキスト＋簡易UIで十分（数値管理ゲームなので情報の見やすさを優先）。

## 5. 技術方針

- **プラットフォーム**: ブラウザ（Web技術）
- 想定スタック: TypeScript + 軽量フレームワーク（React or Svelte、要決定）+ Vite
- サーバ不要の完全クライアント動作。セーブは `localStorage`（JSON1本のステート）
- ゲームロジックはUIから分離した純粋関数群にする（テストとバランス調整シミュレーションが容易になるため）
- 乱数はシード指定可能にする（テスト・デバッグ用）

## 6. スコープ定義

### MVP（最初に作る範囲）

- ターン進行（1日単位）と収支精算
- 依頼: 3種別 × 難易度E〜C 程度、成否判定
- 冒険者: 雇用 / 給料 / 派遣 / 負傷 / シンプルな成長
- 施設: 2種類（受付拡張・医務室）
- 敗北条件（倒産）と ランクE→C までの昇格
- localStorage セーブ / ロード

### MVP に入れないもの（拡張候補）

- 冒険者の性格・スキル・人間関係・引退/死亡ドラマ
- ランダムイベント（依頼の裏切り、盗賊の襲撃、王都からの特命など）
- 競合ギルド・依頼の取り合い
- 難易度B〜S帯のコンテンツとバランス
- 音・グラフィック演出
